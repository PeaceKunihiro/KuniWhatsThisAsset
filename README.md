# KuniWhatsThisAsset

**Unityにインポートする前に、アセットの中身を確認。**

KuniWhatsThisAssetは、`.unitypackage`に含まれるファイルと危険要素を確認するためのWindows向けスタンドアロンツールです。Unity Editorを起動せずにパッケージを直接解析します。

## バージョン・開発状況

**v0.12.0 — フォルダー集約リパッケージ・GNU/PAX長パス対応版**

パッケージの読み込み、内容物一覧、静的な危険要素検出、画像・FBX/OBJ・Prefabの静止プレビューに対応しています。v0.12.0では全内容を保持したフォルダー集約リパッケージと、GNU LongLink/PAXを含む長いパスの読み込みに対応しました。単一EXE配布・手動確認・設定を保持する自己更新も維持します。診断の詳細は既存の警告欄へ集約します。用途推定は未対応です。

## 使い方

1. Windows x64向けの発行済みフォルダーを用意し、`KuniWhatsThisAsset.App.exe`を起動します。
2. 「パッケージを開く」から`.unitypackage`を選択するか、画面にドロップします。
3. 左側のツリーで内容を確認します。Alt＋左クリックで、その枝以下を一括展開・格納できます。
4. ファイルを選択して右側でプレビューを確認します。異常時のみ下部に折りたたまれた通知が表示され、クリックで詳細を確認できます。

発行済みフォルダーは、`KuniWhatsThisAsset.App.exe`と`Libs/`を一式で使用してください。.NET・WPF・SharpAssimp・Assimpは圧縮した単一EXEへ内蔵し、ライセンス原文と配布一覧をLibsへまとめています。ネイティブライブラリは初回実行時に.NETがユーザーの一時フォルダーへ展開します。旧版から初めて切り替える際は新しいフォルダーへZIPを展開すると、古い多数のDLLが残りません。設定は従来の保存先から引き継がれます。配布用ZIPは[Stable](https://github.com/PeaceKunihiro/KuniWhatsThisAsset/tree/master/Stable)にあります。自己完結型のWindows x64版では.NETの別途インストールは不要です。モデル解析には[Microsoft Visual C++ v14 x64ランタイム](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)が必要です。未導入の場合は[公式インストーラー](https://aka.ms/vc14/vc_redist.x64.exe)を利用してください。

起動時の引数でパッケージを指定することもできます。

```powershell
.\KuniWhatsThisAsset.App.exe "D:\Assets\sample.unitypackage"
```

## フォルダーにまとめてリパッケージ

パッケージを読み込んで`File → フォルダーにまとめて保存…`を選びます。まとめ先名の初期値はパッケージ名で、変更できます。配置例を確認して別の.unitypackageへ保存します。

```text
Assets/Avatar/Body.fbx    → Assets/まとめ名/Avatar/Body.fbx
Assets/Materials/A.mat   → Assets/まとめ名/Materials/A.mat
```

全アセットを対象とし、既存GUID・asset・asset.meta・preview等の内容を保持してpathnameを変更します。必要な集約先フォルダーだけを追加し、元にAssets自身のフォルダーエントリがある場合はそのGUID/metaを利用します。元ファイルと既存の出力ファイルは上書きしません。既定の保存名は`元名_Grouped.unitypackage`です。

一時ファイルへストリームで書き込み、GZip/TARの整合性・GUID/配置先・各メンバーのハッシュを読み戻して照合してから確定します。途中失敗・中止時は未完了ファイルを削除します。大量のasset本体をメモリへ保持しません。

StreamingAssets、Gizmos、Editor Default Resources、Standard Assets、Pro Standard Assets、Pluginsは保守的に元の配置を残します。該当する場合、ダイアログで例外を確認して明示チェックした後に保存できます。この場合は完全な1フォルダー構成にはなりません。まとめ先名自体にもEditor/Resources等の特殊名は指定できません。

パス文字列参照やShaderのincludeは自動変更しません。既存GUIDを導入済みのプロジェクトでの再配置、元からのMissing、外部Package依存の解決も保証しません。元の検出内容が消える、安全なパッケージに変換されるという意味ではありません。

**Unity標準Importの検知・通知、AssetDatabase.Refresh/StartAssetEditing、Editor連携、プロジェクトへの直接配置は実装しません。** 保存されたパッケージのUnityへの導入はユーザーが行います。Unity Editorでの実Import確認は未実施です。Fuzzy/Luchikaの実データで全メンバーの保持と再読み込みを確認しています。

### 長いパス

GNU LongLink、PAXのpath/size・属性の適用範囲、USTAR prefixを解釈します。TARの`./`接頭辞も正規化します。パッケージ内パスは32,700文字、pathnameはUTF-8 128 KiBまで、各構成要素は255文字までです。OSの実ファイルパス制限も適用され、超過した名前は切り詰めずエラーにします。

パス情報の合計は初期64 MiBで継続確認します。拡張ヘッダーは1件1 MiB・総64 MiBまで、属性レコードは1ヘッダー4,096件までの構造検証上限を設けます。これは不正/過大なメタデータを拒否するための制約です。拡張制御レコードも読み込み件数・展開総量に含め、長名を解釈した後にパス・GUID構造・重複・リンクを検査します。

## 更新確認

`Help → バージョン情報`を開くと、PCの現地日付で1日1回、[GitHubのStable](https://github.com/PeaceKunihiro/KuniWhatsThisAsset/tree/master/Stable)を自動確認します。確認済み・接続不能・更新なしの場合は、追加通知を出さずリンクを表示します。失敗した試行も当日の回数へ含み、状態はユーザー別のupdate-check.jsonに保存します。

**「更新を確認する」**ボタンは日次制限に関わらず、その場で確認します。最新版・通信失敗などの結果を同じダイアログに表示します。確認APIは5秒・1 MiB上限で、パッケージの内容を送信しません。

新版があれば**「ダウンロードして更新・再起動」**を押すと、アプリ内でZIPとSHA256を取得します。検証が済むまでアプリは終了しません。検証後に別プロセスへ引き継ぎ、終了を待って配布ファイルだけを置換し、再起動します。設定・履歴・ブックマーク・レンダリングキャッシュは保持します。

- GitHubの固定URL、ZIPのSHA256、`Libs/distribution.json`の版・個別ハッシュを確認。パス逸脱・リンク・重複・設定ファイルの混入を拒否します。
- 置換前にバックアップし、途中で失敗した場合は変更分を復元します。配布一覧にないファイルは整理せず、独自ファイルとの衝突時は中止します。旧依存ファイルも、一覧に記録された内容から変更されていないものだけを削除します。
- 更新対象には書き込み権限が必要です。権限不足・取得失敗・不正な更新形式では、現在のアプリを保持して理由を表示します。ダイアログを閉じると未完了のダウンロードを中止します。
- 作業先は`%LOCALAPPDATA%/KuniWhatsThisAsset/Updates/`です。成功した再起動後に作業ファイルを整理し、失敗時は復旧用の作業・backupを残します。ダウンロードは10分・512 MiB、展開は1 GiBまでです。
- 自己更新はv0.11.0以降の単一EXE配布版と対応する配布一覧が対象です。開発用ビルドや未対応形式ではStableのリンクから入手してください。ユーザー操作なしではダウンロード・本体置換を行いません。

## バージョン管理規則

バージョンは`メジャー.マイナー.パッチ`で管理し、0.x系でも以下の規則を適用します。

| 更新幅 | 対象となる変更 | 互換性 |
| --- | --- | --- |
| `+0.0.1`（パッチ） | バグ修正、内部処理修正、軽微なUI修正 | 既存機能・保存データ・APIとの互換性を維持 |
| `+0.1.0`（マイナー） | 新機能追加、機能拡張、大きなUI変更 | 既存との互換性を維持 |
| `+1.0.0`（メジャー） | 保存データ、設定、API、通信仕様などの既存互換性を破壊する変更 | 互換性を破壊 |

複数の変更を含む場合は、最も大きい更新区分を適用します。マイナー更新時はパッチを、メジャー更新時はマイナーとパッチを0に戻します。例：`0.0.1 → 0.0.2`（修正）、`0.0.2 → 0.1.0`（機能追加）、`0.1.0 → 1.0.0`（互換性を破壊する変更）。

## 実装済み機能

### 1. パッケージの内容物一覧・マルウェア検出

内容物の確認と静的解析による危険要素の検出・警告に対応しています。

- `.unitypackage`の読み込み
- ファイル名、パッケージ内パス、形式、サイズの一覧表示
- ディレクトリツリーと形式別ファイル数の表示
- 実行ファイルや不審なコード、異常なアーカイブ構造の検出・警告
- 検出対象ファイルと判定理由の表示
- ツリーのAlt＋左クリック一括展開・格納と、選択履歴の戻る・進む
- 対応テキスト形式のプレビュー（UTF-8 / BOM付きUTF-16 / Shift-JIS）
- 読み込みのキャンセルと解析時間の制限
- CLIによるJSON形式の解析結果出力

### 画像プレビュー

ツリーで画像を選択すると、右側の領域に縦横比を保って表示します。PNG / JPEG / BMP / GIF / TIFF / ICOに対応し、GIF・TIFF・ICOは先頭フレームを表示します。TGA / DDS / PSD / SVGは未対応です。

画像選択時はパッケージを再検証し、選択したアセットの完全なデータをメモリへ読み込みます。ディスク展開や外部URLへのアクセスは行いません。プレビューの入力は64 MiB、各辺16,384ピクセル、合計16,777,216画素（4K正方形を含む）までです。この上限は読み込み継続承認とは独立した画像表示の制限です。表示できない場合はプレビューに短い案内を表示し、詳細を警告欄へ出力します。

### テキストの文字コード

BOMがある場合はUTF-8 / UTF-16を優先し、BOMなしでは厳密なUTF-8を試した後、失敗時にShift-JIS（Windows CP932）を試します。判定は推定であり、両方で解釈できるバイト列はUTF-8を優先します。復号したテキストは表示と危険要素検出の両方に使います。どちらでも復号できない場合は警告します。解析サンプルの末尾で切れた文字は次の文字コードへの切り替え理由にしません。

### 2. 選択した3Dモデルのプレビュー

ツリーでFBX（Binary / ASCII）またはOBJを選択すると静止モデルを表示します。左ドラッグで回転、右・中ドラッグまたはShift＋ドラッグで移動、ホイールでズームできます。「全体表示・正面復帰」で初期表示へ戻ります。

- 頂点数、ポリゴン数（三角形換算）、Mesh数、依存Material数、Bone数、Skinの有無を表示
- **100,000ポリゴン以上、または依存マテリアル10以上**の場合は描画前に高負荷確認。「いいえ」では描画しない
- Unity `.fbx.meta`のマテリアル割り当て、`.mat`の主テクスチャ・色・透過マスクを読み取り、明るい簡易アニメ調照明で表示
- 材質の明示GUID割り当てを優先し、モデルmetaの検索・命名設定に沿って`.mat`を検索。親方向のMaterials / Material / Mat、画像名／材質名／モデル名＋材質名に対応し、PC用・Quest用を区別
- 名前で解決できないFBX/OBJは、同じパッケージ内のPrefabのMesh・材質スロットを逆引きして一意の割り当てを補完。異なるPrefabで割り当てが食い違う場合は自動選択しない
- 未解決の材質・画像は警告欄に理由を表示し、モデルは基本色で表示
- 対応画像形式のテクスチャを最長辺2,048へ縮小して使用。テクスチャ総画素予算は32 Mi画素。未対応・破損・予算超過の画像は単色へフォールバック
- OBJは同じパッケージ内のMTLの基本色に対応。外部ファイル・外部URLは読み込まない

Unity専用シェーダー（lilToon / arktoon等）の輪郭線・MatCap・特殊な影、BlendShape値、スキニング・アニメーション・商品画像のポーズは再現しません。透過は簡易カットアウトで近似します。FBXの初期形状を表示するため、商品画像やUnity上の最終結果と差があります。

バイナリFBXのスキン付きメッシュは、一意に解決できるBindPoseの全体変換があれば静止形状の配置へ使用します。親子の初期回転とバインド時の配置が異なる場合に、髪などが離れる問題を防ぎます。姿勢がない場合・ASCII FBX・通常メッシュは従来のノード変換を使用し、矛盾する姿勢や重複名は自動選択しません。これは静止位置の修正であり、アニメーション・スキニング変形の再生ではありません。SharlenのFBXと通常／FT／alt／alt2のPrefabで確認しました。

ユーザー提供のFuzzy ver.2.00（32,548三角形・5材質）とLuchika ver.1.00（121,966三角形・6材質）でテクスチャ付き表示を確認しました。Luchikaは高負荷確認の対象です。モデル・テクスチャ・検証画像は配布物へ含めません。

モデル解析は別プロセスで行い、60秒・約2 GiBの監視上限を設けています。入力256 MiB、200万頂点・200万三角形まで対応します。これらはパッケージ読み込み上限とは別のプレビュー上限です。プロセス分離はOSのサンドボックスではありません。

キタキツネAkyoのPC/Quest版それぞれのFBX・Prefab、および5000ポリネコメイドのFBX・設定済Prefab、計6経路で自動テクスチャ解決を確認しました。Prefabからの補完は全Prefabを確認できる場合に限り、最大32件・各16 MiB・合計64 MiBを解析します。上限超過や未対応Prefabがあり一意性を確認できない場合は補完を省略します。探索・補完はパッケージ内に限定します。

### Prefabの解析・近似表示

テキスト形式の`.prefab`を選択すると、同じパッケージ内のモデル参照をたどり静止表示します。直接記録されたMeshRenderer＋MeshFilter / SkinnedMeshRendererは、GameObjectと祖先の有効状態、Rendererの有効状態、モデルmetaのMesh IDまたはノード名、材質スロットを解析します。入れ子のPrefabとFBXインスタンスも参照先へ進みます。Unityのモデル階層からRenderer / GameObject / Meshの識別子を生成し、実IDと一致した対象に材質スロット・有効状態の差分を適用します。入れ子IDの合成と明示されたstripped参照により、Variantの継承先へ差分を引き継ぎます。YAMLでUnicodeエスケープされた日本語名にも対応します。

**現在は元モデルの初期形状による近似表示です。** Prefab上の配置変更・Bone姿勢・BlendShape・スクリプトは反映しません。材質と有効状態以外の差分、追加・削除されたComponentの完全再現には未対応です。複数モデルは各元モデルの座標のまま表示するため、Prefabの組み立て位置とは異なる場合があります。解決できないRendererや参照は省略して警告欄に理由を表示します。表示対象がない場合は短い案内を表示します。バイナリPrefab、内蔵Mesh、パッケージ外の参照は表示できません。

選択Prefabの依存関係だけを走査し、パッケージ全体のPrefab件数には左右されません。Prefabは各16 MiB・合計64 MiB・依存32種類、参照深さ8・参照訪問64・元モデル16まで。モデル入力は個別256 MiB・一括512 MiB、metaは個別2 MiB・合計32 MiBまで。循環参照を拒否し、合計形状と材質数に対して従来の高負荷確認を行います。Unityやスクリプトを起動しません。UnityのPrefab形式については[公式資料](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-scenes/text-scene-format/yaml-prefab-serialization)を参照しています。

FUWATTO v26（全414Prefab）の「あのめあMA」と色違いVariantで材質参照を確認しました。現在のFBXに対応するRenderer IDが見つからない材質差分は推測で割り当てず、警告を残します。配置やポーズの違いは上記の近似表示の制約です。

### レンダリングキャッシュ

初回の3D描画後に**正面・側面・平面（上面）**の写真を、各1,024×1,024の透過PNG・正投影で生成します。写真には背景・操作ボタン・情報表示を含めません。再選択時は保存済み写真を表示し、上部ボタンで方向を切り替えられます。「3D表示」で再解析・描画します。高負荷確認は3Dを再描画するときにも適用します。

保存先は`%LOCALAPPDATA%/KuniWhatsThisAsset/RenderCache/`です。パッケージ全体のSHA256・選択アセットGUID・描画処理の改訂番号をキーにし、内容変更時は別キャッシュとします。各写真のハッシュも検証し、破損時は再生成します。上限超過時は最終参照の古いモデルの写真から削除します。写真一式だけで上限を超える場合は保存を省略し、モデル表示を維持します。保存失敗時も3D表示を維持します。

v0.10.1では描画改訂番号を更新し、旧版で作成した写真を再利用せず再生成します。以前のキャッシュは通常の容量管理で整理します。

### 読み込み設定

`Setting → 読み込み設定… → 読み込み設定`タブから変更できます。

| 項目 | 初期値 | 操作 |
| --- | --- | --- |
| Unitypackage上限 | 500 MiB | 整数入力・増減ボタン、または「無制限」 |
| レンダリングキャッシュ上限 | 500 MiB | 整数入力・増減ボタン、または「無制限」 |

1以上の整数MiBを指定します。パッケージ設定は次回の読み込みから適用し、容量上限超過時の継続確認も維持します。「無制限」が解除するのはパッケージファイル自体の容量制限です。展開量・件数・時間・プレビュー固有制限は引き続き適用します。キャッシュ上限を下げると古い写真から削除します。

設定と以下の履歴・ブックマークは`%LOCALAPPDATA%/KuniWhatsThisAsset/preferences.json`へ保存します。

### アドレスバー・ブックマーク

- アドレスバーをクリックすると、正常に開いたパッケージの履歴を最新順で最大10件表示します。同じパッケージは先頭へ移動し、一覧から再度開けます。
- 左の`★`をシングルクリックすると、開いているパッケージを格納した**実フォルダー**をブックマークに追加します。
- `★`のダブルクリックで現在のフォルダーを削除します。シングルクリックの追加はダブルクリック判定が終わってから行います。
- `★`を右クリックすると一覧を表示します。選択したフォルダーを初期位置にしたファイル選択画面からパッケージを開けます。

## UI方針

モデル・画像の表示失敗、未解決材質、キャッシュ保存失敗などの詳細は、パッケージ解析の警告と同じ欄へ集約します。モデル領域には統計・操作案内だけを表示し、保存済みキャッシュの注記も警告欄へ復元します。同じ原因の重複する二次メッセージは抑制します。

警告欄は自動展開しません。通常の表示制限情報だけでは欄を表示せず、警告がある場合に関連情報も含めて表示します。重要度を優先し、同じ重要度では現在のプレビュー診断を先に並べます。アセット選択を変えるとプレビュー診断だけを更新し、パッケージ解析結果は保持します。長い内容はマウスを重ねて全文を確認できます。

異常検出時の警告欄は、展開すると上側の境界をドラッグして高さを変更できます。「別ウィンドウ」で分離し、分離先の「元の画面に戻す」または閉じるボタンで再格納できます。分離先はウィンドウの端からサイズ変更できます。


アプリケーションアイコンはIMGs/KWTA_icon.pngを使用し、EXE用ICOも同じ画像から生成しています。Help → バージョン情報でもアイコンを確認できます。

UI参考画像の配置を維持し、アプリアイコンに合わせたブラウン・クリームの背景、紫の選択色、左ツリー・右プレビューの構成を維持します。セキュリティ通知と検出結果欄は通常非表示で、異常検出時のみ折りたたんで表示します。

- **上部メニュー**：`File / Edit / Setting / Help`。設定・ヘルプなど、頻繁に使わない項目を集約
- **左側**：パッケージの内容物ツリー
- **右側**：モデルプレビューを優先する広い専用領域。パッケージ内パス一覧は配置しない
- **上部操作領域**：パス表示と関連操作

## セキュリティ方針

パッケージは信頼できない入力として扱います。

- パッケージをUnityへインポートしない
- パッケージ内のC#等のスクリプトを実行しない
- パッケージ内のDLL / EXEをロード・実行しない
- プレビューと危険要素の検出は静的解析で行う
- 初版ではディスクへ展開せず、上限付きのストリームから読み取る
- 絶対パス、パストラバーサル、リンク、重複項目、破損を拒否する。容量・件数・解析時間の上限はGUIで継続確認を行う

主な検出・警告対象は次のとおりです。

| 対象 | 例 |
| --- | --- |
| 実行可能なファイル | EXE、DLL、BAT、CMD、PS1、VBS、SCR、Native DLL |
| 注意が必要なコード | 外部プロセス起動、ネットワーク通信、P/Invoke、動的Assemblyロード、Unity Editor自動実行 |
| 形式・パスの異常 | 拡張子と実体形式の不一致、パストラバーサル |
| アーカイブの異常 | 過大なファイル、過剰なファイル数、破損 |

実体形式の確認はMZ、ELF、Mach-O等の代表的なシグネチャを使います。拡張子との照合はPNG / JPEG / GIF / PDF / ZIP / EXE / DLL / SCRに対応しています。DLLのmanaged/native判別は未対応で、いずれも確認対象として扱います。

検出は文字列ルールとシグネチャによる静的解析です。ウイルス定義データベースや外部スキャンサービスは使用しません。**未検出は安全性を保証しません。** 難読化・別名経由の呼び出し・未対応形式は見逃す可能性があり、コメント内の記述等を検出する場合もあります。ネットワーク通信等の検出結果は確認の手がかりであり、マルウェアであるとの断定を意味しません。

### 初期上限

| 項目 | 上限 |
| --- | --- |
| パッケージサイズ | 500 MiB（設定で変更・無制限化可能） |
| 展開相当の総サイズ | 1 GiB |
| TAR内の各メンバー | 256 MiB |
| TAR内の項目数 / アセット数 | 50,000 / 10,000 |
| 解析時間 | 2分（読み込み・解析処理。画面生成は含まない） |
| テキスト解析サンプル | 各メンバー先頭2 MiB、全体32 MiBのサンプル予算 |
| 予算消費後のサンプル | 各メンバー先頭4 KiB |
| テキストの表示 | 先頭32,768文字 |

テキストの解析省略部分は警告します。実体形式の確認はサンプル先頭部分を対象とし、非テキスト形式の内部コードや入れ子のアーカイブは解析しません。標準外メンバーも対応形式の範囲で検査し、警告を表示します。

GUIDディレクトリと`asset / asset.meta / pathname / preview.png`を基本とする構造を想定しています。GNU LongLink（長い名前）・PAX（ローカル/グローバル属性）・USTARに対応します。複数GZipストリーム、リンク・疎ファイル、Windowsで不正なパスは受け付けません。GUIでは容量・件数・解析時間の上限に達すると継続確認ダイアログを表示します。「はい」で今回の読み込みの容量・件数・解析時間の上限をすべて解除し、先頭から再試行します。承認後は他の読み込み上限でも再確認しません。「いいえ」で中止します。次の読み込みは通常の上限に戻ります。テキスト解析のサンプル上限は変更せず、省略を警告します。CLIは対話せず終了コード2を返します。不正なパスや破損の検証は継続時も維持します。上限や対応構造の詳細はアプリの`Setting`メニューでも確認できます。

## 対象環境

Windows x64、.NET 10 / WPFを使用します。Unity Editorは不要です。自己完結型で発行すると.NETランタイムが同梱されます。モデル解析用ネイティブDLLにはMicrosoft Visual C++ v14 x64ランタイムが必要です。OS別の動作確認マトリクスは未整備で、現在は開発環境上での確認です。

## ソースからビルド

Windows上に.NET 10 SDKを用意し、リポジトリのルートで実行します。SharpAssimp 6.0.12をNuGetから取得します。描画は標準WPF Viewport3Dを使用します。

```powershell
dotnet restore KuniWhatsThisAsset.slnx --configfile NuGet.Config
dotnet build KuniWhatsThisAsset.slnx -c Release --no-restore
dotnet run --project tests/KuniWhatsThisAsset.Tests -c Release --no-build
dotnet run --project tests/KuniWhatsThisAsset.UiTests -c Release --no-build
dotnet run --project src/KuniWhatsThisAsset.App -c Release --no-build
```

テストは外部テストフレームワーク不要のコンソール形式です。正常系と不正入力を確認し、失敗時に終了コード1を返します。生成する検証用パッケージは`artifacts/test-packages/`に保存されます。実モデル検証はローカルのユーザー提供データが必要なため通常テストには含めません。手元の指定データで再検証する場合はUIテストへ`--real-models`を渡します。

### Windows x64版の発行

配布用ZIPと対応する`.sha256`ファイルは、プロジェクト直下の`Stable/`にまとめます。展開済みのビルド成果物は`artifacts/`で管理します。

次のコマンドはランタイムパックの取得にネットワーク接続を使用します。出力先はGit管理対象外です。

```powershell
dotnet publish src/KuniWhatsThisAsset.App -c Release -r win-x64 --self-contained true --source https://api.nuget.org/v3/index.json -o artifacts/KuniWhatsThisAsset-v0.9.2-win-x64
```

配布時には.NETランタイムのライセンスと第三者通知も同梱してください。詳細は[技術選定・依存関係](Documents/Development.md)を参照してください。

### CLI

```powershell
dotnet run --project src/KuniWhatsThisAsset.Cli -c Release --no-build -- "D:\Assets\sample.unitypackage"
```

標準出力にJSONを出力します。終了コードは`0`: 解析完了・検出なし、`1`: 解析完了・検出あり、`2`: 引数エラーまたは解析未完了です。

配布用ZIP・SHA256・配布一覧は、PowerShell 7で`./tools/Publish-Stable.ps1`を実行するとStableへ作成されます。発行先は空の新しいartifactsフォルダーを使用します。
