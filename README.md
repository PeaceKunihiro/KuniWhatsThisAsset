# KuniWhatsThisAsset

**Unityにインポートする前に、アセットの中身を確認。**

KuniWhatsThisAssetは、`.unitypackage`に含まれるファイルと危険要素を確認するためのWindows向けスタンドアロンツールです。Unity Editorを起動せずにパッケージを直接解析します。

## バージョン・開発状況

**v0.5.0 — 画像・Shift-JIS対応版**

パッケージの読み込み、内容物一覧、ルールによる静的な危険要素検出を実装しました。モデルプレビュー・用途推定は未対応です。参考画像に沿って大きくUIを変更したため、バージョン管理規則に従いv0.5.0としています。

## 使い方

1. Windows x64向けの発行済みフォルダーを用意し、`KuniWhatsThisAsset.App.exe`を起動します。
2. 「パッケージを開く」から`.unitypackage`を選択するか、画面にドロップします。
3. 左側のツリーで内容を確認します。Alt＋左クリックで、その枝以下を一括展開・格納できます。
4. ファイルを選択して右側でプレビューを確認します。異常時のみ下部に折りたたまれた通知が表示され、クリックで詳細を確認できます。

発行済みフォルダーは、DLL等を含めて一式で使用してください。自己完結型のWindows x64版では.NETの別途インストールは不要です。このリポジトリに実行ファイルは含めていません。ローカルでの発行手順は下記を参照してください。

起動時の引数でパッケージを指定することもできます。

```powershell
.\KuniWhatsThisAsset.App.exe "D:\Assets\sample.unitypackage"
```

## バージョン管理規則

バージョンは`メジャー.マイナー.パッチ`で管理し、0.x系でも以下の規則を適用します。

| 更新幅 | 対象となる変更 | 互換性 |
| --- | --- | --- |
| `+0.0.1`（パッチ） | バグ修正、内部処理修正、軽微なUI修正 | 既存機能・保存データ・APIとの互換性を維持 |
| `+0.1.0`（マイナー） | 新機能追加、機能拡張、大きなUI変更 | 既存との互換性を維持 |
| `+1.0.0`（メジャー） | 保存データ、設定、API、通信仕様などの既存互換性を破壊する変更 | 互換性を破壊 |

複数の変更を含む場合は、最も大きい更新区分を適用します。マイナー更新時はパッチを、メジャー更新時はマイナーとパッチを0に戻します。例：`0.0.1 → 0.0.2`（修正）、`0.0.2 → 0.1.0`（機能追加）、`0.1.0 → 1.0.0`（互換性を破壊する変更）。

## 実装済み機能

### 1. パッケージの内容物一覧・マルウェア検出

内容物の確認と静的解析による危険要素の検出・警告に対応しています。

- `.unitypackage`の読み込み
- ファイル名、パッケージ内パス、形式、サイズの一覧表示
- ディレクトリツリーと形式別ファイル数の表示
- 実行ファイルや不審なコード、異常なアーカイブ構造の検出・警告
- 検出対象ファイルと判定理由の表示
- ツリーのAlt＋左クリック一括展開・格納と、選択履歴の戻る・進む
- 対応テキスト形式のプレビュー（UTF-8 / BOM付きUTF-16 / Shift-JIS）
- 読み込みのキャンセルと解析時間の制限
- CLIによるJSON形式の解析結果出力

### 画像プレビュー

ツリーで画像を選択すると、右側の領域に縦横比を保って表示します。PNG / JPEG / BMP / GIF / TIFF / ICOに対応し、GIF・TIFF・ICOは先頭フレームを表示します。TGA / DDS / PSD / SVGは未対応です。

画像選択時はパッケージを再検証し、選択したアセットの完全なデータをメモリへ読み込みます。ディスク展開や外部URLへのアクセスは行いません。プレビューの入力は64 MiB、各辺16,384ピクセル、合計1,600万画素までです。この上限は読み込み継続承認とは独立した画像表示の制限です。表示できない場合はプレビュー領域に理由を表示します。

### テキストの文字コード

BOMがある場合はUTF-8 / UTF-16を優先し、BOMなしでは厳密なUTF-8を試した後、失敗時にShift-JIS（Windows CP932）を試します。判定は推定であり、両方で解釈できるバイト列はUTF-8を優先します。復号したテキストは表示と危険要素検出の両方に使います。どちらでも復号できない場合は警告します。解析サンプルの末尾で切れた文字は次の文字コードへの切り替え理由にしません。

## UI方針

異常検出時の警告欄は、展開すると上側の境界をドラッグして高さを変更できます。「別ウィンドウ」で分離し、分離先の「元の画面に戻す」または閉じるボタンで再格納できます。分離先はウィンドウの端からサイズ変更できます。


アプリケーションアイコンはIMGs/KWTA_icon.pngを使用し、EXE用ICOも同じ画像から生成しています。Help → バージョン情報でもアイコンを確認できます。

UI参考画像の配置を維持し、アプリアイコンに合わせたブラウン・クリームの背景、紫の選択色、左ツリー・右プレビューの構成を維持します。セキュリティ通知と検出結果欄は通常非表示で、異常検出時のみ折りたたんで表示します。

- **上部メニュー**：`File / Edit / Setting / Help`。設定・ヘルプなど、頻繁に使わない項目を集約
- **左側**：パッケージの内容物ツリー
- **右側**：モデルプレビューを優先する広い専用領域。パッケージ内パス一覧は配置しない
- **上部操作領域**：パス表示と関連操作

## セキュリティ方針

パッケージは信頼できない入力として扱います。

- パッケージをUnityへインポートしない
- パッケージ内のC#等のスクリプトを実行しない
- パッケージ内のDLL / EXEをロード・実行しない
- プレビューと危険要素の検出は静的解析で行う
- 初版ではディスクへ展開せず、上限付きのストリームから読み取る
- 絶対パス、パストラバーサル、リンク、重複項目、破損を拒否する。容量・件数・解析時間の上限はGUIで継続確認を行う

主な検出・警告対象は次のとおりです。

| 対象 | 例 |
| --- | --- |
| 実行可能なファイル | EXE、DLL、BAT、CMD、PS1、VBS、SCR、Native DLL |
| 注意が必要なコード | 外部プロセス起動、ネットワーク通信、P/Invoke、動的Assemblyロード、Unity Editor自動実行 |
| 形式・パスの異常 | 拡張子と実体形式の不一致、パストラバーサル |
| アーカイブの異常 | 過大なファイル、過剰なファイル数、破損 |

実体形式の確認はMZ、ELF、Mach-O等の代表的なシグネチャを使います。拡張子との照合はPNG / JPEG / GIF / PDF / ZIP / EXE / DLL / SCRに対応しています。DLLのmanaged/native判別は未対応で、いずれも確認対象として扱います。

検出は文字列ルールとシグネチャによる静的解析です。ウイルス定義データベースや外部スキャンサービスは使用しません。**未検出は安全性を保証しません。** 難読化・別名経由の呼び出し・未対応形式は見逃す可能性があり、コメント内の記述等を検出する場合もあります。ネットワーク通信等の検出結果は確認の手がかりであり、マルウェアであるとの断定を意味しません。

### 初期上限

| 項目 | 上限 |
| --- | --- |
| パッケージサイズ | 512 MiB |
| 展開相当の総サイズ | 1 GiB |
| TAR内の各メンバー | 256 MiB |
| TAR内の項目数 / アセット数 | 50,000 / 10,000 |
| 解析時間 | 2分（読み込み・解析処理。画面生成は含まない） |
| テキスト解析サンプル | 各メンバー先頭2 MiB、全体32 MiBのサンプル予算 |
| 予算消費後のサンプル | 各メンバー先頭4 KiB |
| テキストの表示 | 先頭32,768文字 |

テキストの解析省略部分は警告します。実体形式の確認はサンプル先頭部分を対象とし、非テキスト形式の内部コードや入れ子のアーカイブは解析しません。標準外メンバーも対応形式の範囲で検査し、警告を表示します。

GUIDディレクトリと`asset / asset.meta / pathname / preview.png`を基本とする構造を想定しています。PAX/GNU拡張レコード、複数GZipストリーム、Windowsで不正なパスは受け付けません。GUIでは容量・件数・解析時間の上限に達すると継続確認ダイアログを表示します。「はい」で今回の読み込みの容量・件数・解析時間の上限をすべて解除し、先頭から再試行します。承認後は他の読み込み上限でも再確認しません。「いいえ」で中止します。次の読み込みは通常の上限に戻ります。テキスト解析のサンプル上限は変更せず、省略を警告します。CLIは対話せず終了コード2を返します。不正なパスや破損の検証は継続時も維持します。上限や対応構造の詳細はアプリの`Setting`メニューでも確認できます。

## 対象環境

Windows x64、.NET 10 / WPFを使用します。Unity Editorは不要です。自己完結型で発行すると.NETランタイムが同梱されます。OS別の動作確認マトリクスは未整備で、現在は開発環境上での確認です。

## ソースからビルド

Windows上に.NET 10 SDKを用意し、リポジトリのルートで実行します。初版は外部NuGetライブラリを使用しません。

```powershell
dotnet restore KuniWhatsThisAsset.slnx --configfile NuGet.Config
dotnet build KuniWhatsThisAsset.slnx -c Release --no-restore
dotnet run --project tests/KuniWhatsThisAsset.Tests -c Release --no-build
dotnet run --project tests/KuniWhatsThisAsset.UiTests -c Release --no-build
dotnet run --project src/KuniWhatsThisAsset.App -c Release --no-build
```

テストは外部テストフレームワーク不要のコンソール形式です。正常系と不正入力を確認し、失敗時に終了コード1を返します。生成する検証用パッケージは`artifacts/test-packages/`に保存されます。実際のUnityエクスポートによる互換性検証は今後の課題です。

### Windows x64版の発行

次のコマンドはランタイムパックの取得にネットワーク接続を使用します。出力先はGit管理対象外です。

```powershell
dotnet publish src/KuniWhatsThisAsset.App -c Release -r win-x64 --self-contained true --source https://api.nuget.org/v3/index.json -o artifacts/KuniWhatsThisAsset-v0.5.0-win-x64
```

配布時には.NETランタイムのライセンスと第三者通知も同梱してください。詳細は[技術選定・依存関係](Documents/Development.md)を参照してください。

### CLI

```powershell
dotnet run --project src/KuniWhatsThisAsset.Cli -c Release --no-build -- "D:\Assets\sample.unitypackage"
```

標準出力にJSONを出力します。終了コードは`0`: 解析完了・検出なし、`1`: 解析完了・検出あり、`2`: 引数エラーまたは解析未完了です。
